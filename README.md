# AI ComfyUI Studio：ComfyUI 规则化管理

个人研究用的 ComfyUI（一台 RTX PRO 6000 96GB 的 Linux 推理机，正式实例 8188、测试实例 8191）的管理资料：规范、每次执行的记录、异常调查、工作流登记卡和索引。不放模型权重、图片、视频。内网地址、个人目录名已脱敏。

## 新会话接手先读什么（按顺序）

1. `00_ComfyUI规范_v1.2.md`：ComfyUI 规范（条号 0–24，第 20 条已删，现行 24 条；旧版 v1.1 留着对照）。跑任何任务前先照它自查。
2. `00_ComfyUI管理_设计书.md`：这套管理怎么运作（收集器、指纹、异常规则、登记卡、索引、目录、GitHub）；文末「实现进度」是现状。
3. `anomalies/待查表.md`：现在有哪些异常、查到什么程度。
4. `workflows/总表.md`：有哪些工作流、哪个推荐、多快；点进 `workflows/cards/` 看单张登记卡。
5. `index/`：从模型找工作流（`模型→工作流.md`）、从工作流找模型、从脚本找工作流，模型清单。

## 目录

| 目录 | 内容 | 谁写 |
|---|---|---|
| `runs/runs.jsonl` | 每次执行一行（提交、开始、结束、执行秒、指纹、模型、参数、输出 md5、质量闸、显存、提交者） | 收集器自动 |
| `anomalies/` | 待查表、工单（json）、调查记录 | 自动开单，人写结论 |
| `workflows/` | 总表、每个指纹一张登记卡 | 统计自动；用途、质量、用户评价、测试总结人写 |
| `index/` | 三张索引、模型清单、指纹名、前缀表 | 自动；指纹名和前缀表人写 |
| `tools/` | 收集器、异常检测、索引、显存采样、模型 md5、同步脱敏、提交工具 comfy_safe | |
| `试算_1117/` | 设计时拿 11-17 的 148 条历史试算的脚本和结果 | |

## 几条要紧的

- 收集器只读：只调 `GET /history`、`/queue`、`/system_stats`、`/object_info`，不提交任务、不释放显存、不中断。
- 比耗时只用 `/history` 的执行秒（或日志「Prompt executed in」），不用脚本从提交算起的时间（规范第 22 条）。
- 维护人：模型学习频道。规范改动先报总督导，再由用户定。
